The format · Version 0.1 draft

A menu, described in plain JSON.

A manifest adds a menu to media that already exists: a film and its extras, a season of episodes, an imported DVD. It holds backgrounds, buttons, highlight art, remote-control navigation and actions. Every action points at existing media. The manifest never contains video.

Anatomy

What's inside

A short manifest with one menu and two buttons. Real ones add chapters, more menus, motion backgrounds and state art; the shape stays the same.

  • media: what can be played, by id, pointing at your files
  • menus: canvases, backgrounds and buttons with highlight states
  • actions: what each button does
  • fallback: a plain list any player can show
{
  "format": "openvideomenu",
  "version": "0.1",
  "title": { "name": "Sintel", "year": 2010 },
  "media": {
    "feature": { "ref": "Sintel (2010).mp4" },
    "trailer": { "ref": "Trailers/Sintel Trailer.mp4" }
  },
  "menus": {
    "main": {
      "canvas": { "width": 1280, "height": 720 },
      "background": { "image": "menus/main.jpg" },
      "buttons": [
        { "id": "play", "rect": [780, 430, 420, 64],
          "states": { "selected": { "image": "menus/play-on.png" } },
          "nav": { "down": "trailer" },
          "action": { "type": "play", "media": "feature" } },
        { "id": "trailer", "rect": [780, 510, 420, 64],
          "nav": { "up": "play" },
          "action": { "type": "play", "media": "trailer" } }
      ]
    }
  },
  "rootMenu": "main",
  "fallback": [
    { "label": "Movie", "items": [
      { "label": "Play", "action": { "type": "play", "media": "feature" } }
    ] }
  ]
}

Concepts

Built from a few simple parts

Media

Each playable title gets an id and a reference: a path next to the manifest, a URL, or an id your media server resolves. Chapters give scene selection its start times.

Menus and buttons

A menu is a canvas with a background and buttons. Buttons have a rectangle, highlight art for their normal, selected and activated states, and where each direction of the remote goes.

Actions

play, playAll, goto, back, resume and set. After playback the viewer returns to the menu, and an action can run afterwards.

Motion

Background video and music that loop from a point, buttons that appear after the intro, and transition clips between menus. Any key skips.

Variables

Named numbers that a menu sets, such as the chosen soundtrack, and that playback reads to pick audio and subtitle tracks.

Fallback list

Every manifest also lists its titles as plain groups, so basic players, voice assistants and search can offer the extras too.

Bundles

One tidy file per menu

A menu set can ship as Title.ovmz: a ZIP holding manifest.json and its art, every entry stored uncompressed. Menu art is already compressed, so this costs nothing in size, and servers can stream any file inside, including a range of a motion clip, without unpacking.

Bundles are recommended for manifests with local art. A loose Title.openvideomenu.json with a menus/ folder stays valid, and readers support both.

Levels

LevelA player supports
0 · BasicThe fallback list and playback. About an afternoon's work.
1 · MenusCanvases, backgrounds, buttons and states, navigation, chapters, play, play all, resume and submenus.
2 · EnhancedWhat a player shows and plays: motion backgrounds and music, intros, transitions, timeouts, angles, soundtrack and subtitle choice, buttons over the film, still frames, and the remote's Menu key.
3 · Disc logicEverything a DVD's programs do: variables, conditions, shared actions, the disc's resume point, timers and parental requests. A menu that needs it says so, and simpler players show its list instead.

Compatibility promise

Written once, readable forever

From version 1.0 the format only grows. A manifest written today keeps working in every future reader.

  • Old manifests work forever
  • Fields are never removed or given a new meaning
  • Readers ignore fields they don't know; vendor extensions start with x-
  • Every manifest carries a plain fallback list
  • "Compatible" means passing the conformance suite for a stated version
