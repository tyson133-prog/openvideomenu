Developers

Add menus to your player.

Support is free to add, in any software, with no fees and no permission needed. A language-neutral conformance suite tells you exactly how menus must behave, so every player behaves the same.

For player developers

Three small pieces

Navigation is a pure state machine you can reuse or re-implement. Your player supplies the rest.

  1. Playback

    Play a URL from a time; report when it ends or when the viewer stops it.

  2. Input

    Turn remote or keyboard presses into up, down, left, right, enter and back.

  3. Media resolver

    Turn a media reference into something playable: a file path, a stream, an item on your server.

// The whole navigation model: state in, event in,
// new state and effects out.
const { state, effects } = step(manifest, state, {
  type: "press", key: "down"
});
// effects: play, activated, transition, skipIntro, exit

Start at Level 0

Showing the fallback list and playing items is Level 0, and takes about an afternoon. Menus (Level 1), enhanced features (Level 2) and a disc's full logic (Level 3) build on the same manifest.

Conformance

"Compatible" has a precise meaning

Each conformance case is a manifest plus a script of input events and the states and effects that must follow. Run them in any language; if they pass, your player is compatible with that version. The TypeScript, .NET and Roku implementations all run the same files.

Link to the conformance suite 
{ "event": { "type": "press", "key": "enter" },
  "expect": {
    "mode": "playing",
    "effects": [
      { "type": "activated", "menu": "main", "button": "all" },
      { "type": "play", "media": "e1", "start": 0 }
    ]
  } }

TypeScript

The reference validator and navigator, with no dependencies, plus a web player with a 10-foot UI and pluggable playback.

.NET

Read, write and validate manifests, pack and read bundles, and run navigation, on .NET 8 and 10. It gives exactly the same results as the reference implementation.

dotnet add package OpenVideoMenu · on NuGet

DVD import: OpenVideoMenu.Dvd, and the ovm-dvd tool (dotnet tool install -g OpenVideoMenu.Dvd.Tool).

Tools for authors and importers

Validate, preview, bundle

The openvideomenu command checks manifests and bundles with the same rules players use, previews menus in a browser with remote-style keys, and packs a manifest and its art into a bundle.

Importers that turn DVD menus into manifests follow the DVD profile. Help wanted: a Blu-ray (HDMV) import profile, mapping interactive-graphics buttons and HDMV commands to the format.

openvideomenu validate "Sintel (2010)"
openvideomenu preview  "Sintel (2010)"
openvideomenu pack     "Sintel (2010)/Sintel (2010).openvideomenu.json"
openvideomenu unpack   "Sintel (2010)/Sintel (2010).ovmz"

Servers

Serve menus from your media server

A small read-only HTTP API lets apps list the menus in a library and fetch manifests and art, with bundles served as folders and byte ranges for motion clips. Servers advertise it on the local network with DNS-SD (_openvideomenu._tcp). The Jellyfin plugin and the Plex menu server both implement it.

Using the name

Say your software "supports Open Video Menu" any time. Say "compatible" once it passes the conformance suite. Please don't name products "Open Video Menu"; "Acme Player, with Open Video Menu support" is perfect.
